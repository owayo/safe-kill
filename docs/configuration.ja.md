# 設定

`safe-kill` が読む設定ファイルは `~/.config/safe-kill/config.toml` の 1 つだけです。プロジェクトごとの設定や、別のファイルを指定するオプションはありません。ファイルが無いときは既定値で動き、許可リストは空、拒否リストは下の既定のもの、`--port` は無効になります。

## 設定項目

```toml
# 親子関係チェックをバイパスするプロセス（慎重に使用）
[allowlist]
processes = ["trusted-worker"]

# 追加で絶対に終了できないプロセス（許可リストより優先）
# システム保護の既定 denylist は維持され、この設定はそこへ追加されます
[denylist]
processes = ["postgres"]

# --port オプションで許可するポート
# 指定しない場合、--port オプションは無効（ポート指定でのkillは不可）
# 有効な値は 1-65535。ポートや範囲として読めない指定（0 を含む範囲を含む）は
# 設定エラーになります。
[allowed_ports]
ports = ["1420", "3000-3010", "5173", "8080"]
#   - 1420: Tauri開発サーバー
#   - 3000-3010: Node.js開発サーバー
#   - 5173: Vite開発サーバー
#   - 8080: HTTP代替ポート
```

| テーブル | キー | 意味 |
|---------|-----|------|
| `[allowlist]` | `processes` | 親子関係チェックを省くプロセス名。拒否リスト・信頼ルート・PID 1・自己破壊防止の保護は外れない |
| `[denylist]` | `processes` | 絶対に終了できないプロセス名。既定の拒否リストに追加される |
| `[allowed_ports]` | `ports` | `--port` で対象にできるポート。単一ポート（`"8080"`）か範囲（`1 <= 開始 <= 終了 <= 65535` の `"開始-終了"`。例 `"3000-3010"`）で書く。読めない指定（`0` を含む範囲 `"0-3010"`、逆順の範囲、`65535` を超える値、ASCII の `-` 以外のダッシュ）は読み飛ばさず、ファイル全体を設定エラー（終了コード 3）にする。有効なポート全体を許可するなら `1-65535` |

`--port` による終了は、設定したポートについて親子関係チェックを省きます。別のターミナルで起動したまま残った開発サーバーを止めるときに使えます。自己破壊防止・拒否リスト・信頼ルートと PID 1 の保護は、この場合もそのまま効きます。

## プロセス名

`[allowlist]`・`[denylist]`・`--name` が照合するのは、パッケージ名やコマンドラインの表示名ではなく、OS が報告するプロセス名です。

- **macOS**: 実行ファイルのファイル名。Next.js の開発サーバーは表示名を `next-server (v15…)` に変えますが、名前は `node` です。
- **Linux**: カーネルの `comm` で、先頭 15 バイトに切り詰められます。プログラム自身が書き換えることもでき（Node.js の `process.title` がそうです）、同じサーバーは `next-server (v1` になります。

`safe-kill --list` に出てくるプロセスなら、NAME 列の値をそのまま書いてください。Linux では `ps -o comm= -p <PID>` でも確認できます。

許可リストと `--name` は完全一致で照合します。許可リストは同じ名前のすべてのプロセスについて親子関係チェックを省くので、`node` のような汎用的な名前は避けてください。Linux の拒否リストでは、15 バイトを超えるエントリは先頭 15 バイトとも一致します（`gnome-terminal-server` は `gnome-terminal-` を保護します）。長い名前でも保護が外れないようにするためです。先頭 15 バイトが同じ別のプロセスも保護されますが、安全側に倒れるだけです。

## デフォルト拒否リスト

以下のシステムプロセスはデフォルトで保護されます:

**macOS**: `launchd`, `kernel_task`, `WindowServer`, `loginwindow`, `Finder`, `Dock`, `SystemUIServer`, `ControlCenter`

**Linux**: `systemd`, `init`, `kthreadd`, `dbus-daemon`, `gnome-shell`, `Xorg`, `sshd`

ユーザー定義の `[denylist]` はこの既定保護に追加されます。カスタマイズしてもシステムプロセスの保護は解除されません。

macOS 12 以降では、AirPlay レシーバーが `ControlCenter` の中で動き、TCP の 5000 番と 7000 番で待ち受けます。5000 番は Flask の既定のポートでもあるので、`[allowed_ports]` に `5000` を入れていると、自分のサーバーが止まった後の `safe-kill --port 5000` が `ControlCenter` を見つけます。既定の拒否リストがこれを拒否します。開発でこのポートを使うなら、システム設定で AirPlay レシーバーを切ってください。

## 読み込み時の検証

`config.toml` が存在するのにアクセス・読み込み・解析できない場合、または未知フィールドや不正な `[allowed_ports]` の指定を含む場合、kill/list 系コマンドは設定エラーとして停止します。既定値へ倒すのは設定パスがまったく存在しない場合だけで、それ以外の理由でたどり着けない場合（途中の階層が通常ファイル、symlink のループ、権限エラーなど）も設定エラーにします。通常ファイルと、通常ファイルへ解決できる symlink は読み込めます。壊れた symlink（ファイル自体、または上の階層のディレクトリ）、ディレクトリ・FIFO・デバイスへ解決されるパスは読み込み前に拒否し、管理対象の設定消失によるカスタム保護の暗黙解除や、特殊ファイルによる待機・無制限読み込みを防ぎます。

設定ファイルの場所は `HOME`（未設定か空ならユーザーデータベース）から決めます。`HOME` が相対パス（展開されずに残った `HOME='~'` など）なら設定エラー（終了コード 3）で停止し、`init` も何も作りません。カレントディレクトリを基準に解決すると、エージェントがたまたま作業しているリポジトリが `[allowlist]` や `[allowed_ports]` を差し込めてしまうためです。

## `safe-kill init` で作る

`safe-kill init` はコメント付きの `config.toml` を書き出します。`[allowed_ports]` は上の例と同じポートで有効になり、`[allowlist]` と `[denylist]` はコメントアウトした例として入ります。

設定ファイルが既に存在する場合、`init` は上書き前に確認を求めます（`--force` で確認を省略）。上書きするのは `y` か `yes`（大文字小文字は区別せず、前後の空白は無視）と答えたときだけです。それ以外の応答（空行、入力の終わり、UTF-8 として読めない入力を含む）は拒否として扱い、既存ファイルを変更せず正常終了します（終了コード 0）。ファイルの作成・書き込みの失敗と、壊れた symlink や特殊ファイルの拒否は設定エラー（終了コード 3）です。確認の文面を書き出せない場合は、応答を読まずに停止します（終了コード 255）。

設定ファイルが symlink の場合（`~/.config/safe-kill/config.toml -> ~/dotfiles/safe-kill.toml` のような dotfiles 管理の一般的な運用）もそのまま使えます。`init` はリンクを追従して実体ファイルを更新し、symlink 自体は維持します。ただし書き換わるのは指定したパスそのものではないため、確認プロンプトと成功メッセージの両方で解決後の実体パスを開示します。**壊れた** symlink（リンク先が存在しない）は、リンク先へ黙ってファイルを新規作成せず拒否します（`--force` を付けても終了コード 3）。

`init` が受け入れるのは通常ファイル、または通常ファイルへ解決できる symlink だけです。ディレクトリ・FIFO・デバイスと、それらへ解決される symlink は open 前に拒否するため、`--force` でも FIFO で待ち続けたりデバイスへ書き込んだりしません。検証済みの親ディレクトリは device/inode を確認してファイルディスクリプタで固定し、そこから non-blocking・symlink 非追従で書き込み先を開きます。取得したファイルの device/inode も truncate 前に再検証します。open 前のパス置換は fail-closed で停止し、open 後にパスが変わっても固定済みのファイルディスクリプタから別ファイルへ書き込みを誘導されません。

新規設定では、`init` は `~/.config/safe-kill` を `0700`、`config.toml` を `0600` で作成します。作成時の権限上限を明示するため、呼び出し元が `umask 000` でも allowlist・denylist・許可ポート設定を他ユーザーが書き換えられる権限にはなりません。より厳しい `umask` はそのまま有効です。
