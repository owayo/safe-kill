# 開発

準備の手順と標準の `make` ターゲットは、README の[開発](../README.ja.md#開発)の節にあります。このページではテストについて説明します。

## テストの一部だけを実行する

| コマンド | 実行するテスト |
|---------|---------------|
| `make test` | すべてのテスト（ライブラリ・バイナリ・統合・E2E） |
| `make test-integration` | 統合テストだけ（`tests/integration_tests.rs`） |
| `make test-e2e` | E2E テストだけ（`tests/e2e_tests.rs`） |

名前に特定の語を含むテストだけを実行するときは、その語を mise 経由で `cargo test` に渡します。例: `mise exec -- env -u SAFE_KILL_ROOT_PID cargo test --locked ancestry`。`make` のターゲットは `SAFE_KILL_ROOT_PID` を外して実行します。ライブラリと統合テストはこの変数を同じプロセス内で読むため、エージェントのセッションなどで設定されたままだと信頼ルートが変わります。並列に走るテストの中から安全に外す方法は無いので、起動前に外します。

## テストカバレッジ

件数は macOS での値です。ライブラリテストには OS 固有のものが含まれるため、Linux では件数が変わります。

- **ライブラリユニットテスト**: 全モジュールを網羅する571テスト。実プロセスツリーでは作れない状況を、データを注入して検証しています。ancestry 探索の停止条件（深度上限・親 PID の循環・PID 1 到達・直接の祖先の消失）、信頼ルートの検出（親がシェル、シェルが exec して消えた、祖父が PID 1 や subreaper、祖父が見つからない）、kill 直前の親チェーンの再検証（2 回の取得の間に祖先が入れ替わった・対象が付け替えられた・消えた、取得の順序）、`--name` の処理順（子を親より先に、PID の周回、循環）がその例です。macOS のポート検出は、差し替えられる libproc の呼び出し口を通して検証しています。失敗した問い合わせのバッファが対象ポートのリスナーそのものの形をしていても受け入れないこと、列挙と問い合わせの間に実際の FD を閉じたり置き換えたりしても証拠に数えないことを確かめます。`--port` のポリシーは待ち受けソケットを引き継いだ実際の子プロセスで、シグナルの送信は差し替えた送信関数で（PID 0 や -1 へ届く余地を作らない）確かめます。エスケープする文字の集合は Unicode 17.0 のデータと全 code point で照合し、設定ファイルとして FIFO を開いても待たないことも確かめます
- **バイナリユニットテスト**: CLI出力ユーティリティの58テスト。実際の書き込み関数を通したサニタイズ、help の文言、使用方法エラーの表示、出力失敗時の終了コードの規則を含む
- **統合テスト**: 実際のプロセスツリーを使用した80テスト。一時プロセス名にテストランナーの PID と連番を含め、Linux の `comm` 15バイト上限を守りながら複数の `cargo test` を並行実行しても衝突しないようにしています。一部成功・一部拒否が混在するバッチは、同名の子孫プロセスと孤児プロセス（親が PID 1 へ付け替わったもの）を並べて検証します。`--name` は名前でしか対象を選べないため、kill 可否が異なる同名プロセスを作るにはこの方法しかありません。同名の親子（自分自身を起動する `/bin/bash` への symlink）では、SIGKILL と SIGTERM のどちらでも `--name` が孤児を残さないことを確かめます
- **E2Eテスト**: CLI動作を検証する134テスト。相対パスの `HOME` と不正な `[allowed_ports]` の指定が設定エラーになること、PID 指定でポリシーに拒否された場合の終了コード、緩い `umask` 下でも設定が非公開権限で作成されること、すべての入口で help が英語であること、clap の使用方法エラーに埋め込まれた制御文字が削除されずにエスケープされること、`ulimit -f 0` で再現した出力失敗の扱い（実際の kill は警告付きで 0、`--list` と dry-run は 255）を含む。バイナリは常に空の `HOME` で、`SAFE_KILL_ROOT_PID` を外して起動するので、開発者の設定で結果が変わったり、テストが実際の kill になったりしない

テストがシグナルを送るのは自分で起動したプロセスだけです。`--port` のテストは、テスト自身がリスナーを持つ場合を除いて `--dry-run` で実行します。終了の確認は回収済みの PID へのシグナルではなく子プロセスの終了ステータスで行い、dry-run のテストで固定 PID を使うときは存在しない `999999999` を使います。

設定初期化では、検証後に親ディレクトリが同じ inode を指す symlink へ置換された場合と、既存設定ファイルが削除された場合の拒否も検証します。権限の E2E テストは、緩い `umask` で権限上限を守ることに加え、厳しい `umask` で設定を `0400` として作成し、権限を広げずに読み込めることを確かめます。
